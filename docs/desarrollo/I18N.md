# Idiomas: cómo se marca y se traduce un texto

El plan completo está en [`docs/planes/PLAN-I18N.md`](../planes/PLAN-I18N.md). Esta página
explica cómo se trabaja: cómo marcar un texto, cómo se traduce y qué se compila.

## La regla

**Un idioma son archivos, nunca código.** Cada idioma tiene dos:

- su perfil: `assets/idiomas/<código>.json`, con el nombre en su idioma, el locale, la
  dirección, la regla de plurales y los respaldos;
- su catálogo: `i18n/ba_<código>.ts`.

`if (idioma == "en")` está prohibido: lo que cambia entre idiomas va en el perfil, y
`tests/test_i18n.py` lo busca en el código.

El **texto original** es el español rioplatense con el que está escrito el código. Lo que no
tiene traducción sale tal cual. Por eso el español solo tiene un `.ts` con los plurales.

## Marcar un texto

| Dónde | Cómo |
|---|---|
| QML | `qsTr("Conferencia")`, `qsTr("%n invitado", "", n)` |
| C++ con Qt (un `QObject`) | `tr("Conferencia")` |
| C++ sin Qt (núcleo, gateway, launcher) o fuera de una clase | `ba::i18n::traducir("contexto", "Conferencia")` |
| En el idioma del evento o del invitado | `ba::i18n::En(evento.idioma).traducir("graficos", "En vivo")` |
| Web (JS) | `t("Entrar a la sala")`, `t("%n invitado", {n})` |
| Web (HTML) | `data-i18n="Entrar"`, `data-i18n-placeholder`, `data-i18n-title`, `data-i18n-aria-label` |

- Los datos van con `%1`, `%2`, que se llenan con `ba::i18n::llenar(...)`, `.arg()` en QML o
  `BAi18n.llenar(...)` en la web. **Nunca** una frase armada con pedazos
  (`"Grabando " + nombre`), porque el orden de las palabras cambia con el idioma.
- Para los plurales se usa `%n`: la traducción tiene tantas formas como pida la regla del idioma.
- Si el mismo texto tiene dos sentidos, va la desambiguación: `qsTr("Salida", "audio")`.
- **No se marcan** los nombres de herramientas MCP ni sus parámetros, las claves de JSON
  o de ajustes, ni los nombres de carpetas en disco. Son API.

## Actualizar y traducir

```sh
make i18n-actualizar      # lupdate: textos nuevos al .ts sin traducir, los que ya no están se van
```

Si marcaste un texto con `%n`, completá sus dos formas en español en `i18n/ba_es.ts`
(«%n invitado» / «%n invitados»): sin eso el programa dice «5 invitado», y
`tests/test_i18n.py` no pasa.

Después se traduce el `.ts` con Qt Linguist o con un modelo, y se marca cada texto como
terminado. Una traducción sin terminar sale en el original.

## Qué se compila

`tools/i18n/ts-a-json.py` pasa cada `.ts` a `data/i18n/<código>.json`. Ese catálogo es el
mismo para todos los que traducen:

- **El núcleo** (`ba::i18n`).
- **La interfaz:** `arranque/TraductorQt` le pregunta al núcleo, así no hace falta un `.qm`
  ni `lrelease`.
- **La web:** el gateway lo sirve en `/comun/i18n/` y lo usa `/comun/i18n.js`.

Los perfiles van a `data/idiomas/`. Para compilar solo hace falta un Python.

## Probar

- **El idioma de un proceso:** `BA_IDIOMA=en` pisa al guardado. Por ejemplo,
  `open BroadcastAppliance.app --env BA_IDIOMA=xx`.
- **El pseudo-idioma `xx`:** cada texto traducido sale `⟦Çöñfërëñçïä····⟧`. Lo que se ve
  sin `⟦ ⟧` se escapó, y lo que se corta no aguanta un idioma más largo.
- **Tests:** `tests/test_i18n.py` y `src/core/tests/test_i18n.cpp`.

## Sumar un idioma

1. Copiá un perfil de `assets/idiomas/` con el código nuevo y completalo.
2. Corré `make i18n-actualizar` (crea `i18n/ba_<código>.ts`).
3. Traducilo.

Lo que no esté traducido sale de los respaldos del perfil y, al final, en el original.
